Terminal IDE User Guide

A complete development environment that runs entirely in the terminal: Neovim with LazyVim, tmux, lazygit and a set of fast search tools. Built for a TypeScript project on a Raspberry Pi (Debian 12, arm64), and installed without sudo.

Overview

The setup combines a few small tools instead of one large application. Each does one job, and they share a single terminal window.

Neovim + LazyVim

The editor. Fuzzy file and text search, file tree, completion, diagnostics and formatting.

tmux

Splits the terminal into panes and keeps your session alive when you disconnect.

lazygit

A full-screen git interface: stage, commit, branch and rebase with a few keys.

Mason

Installs language servers, linters and formatters from inside Neovim.

fzf, fd, bat, ripgrep

Fast search and preview tools that LazyVim's pickers rely on.

Quick start

Run the launcher from any terminal:

hb

hb is a short shell script at ~/.local/bin/hb. It opens a tmux session named hb in the project directory, or re-attaches to it if it is already running. The session has two windows.

nvimeditor
claudeClaude Code
npx vitesttest watcher

Window 1 (code) holds the three panes above. Window 2 (shell) is a plain shell for one-off commands.

Leave and come back. Press Ctrl+b then d to detach. Everything keeps running. Type hb again to resume exactly where you were.

To stop the session completely: tmux kill-session -t hb.

tmux

Every tmux shortcut starts with the prefix, which is Ctrl+b. Press the prefix, release it, then press the key below. Mouse support is on, so you can also click panes and drag borders.

Neovim (LazyVim)

LazyVim is a ready-made Neovim configuration. Its main idea: press Space (the leader key) and wait. A menu called which-key shows every available command. You do not need to memorize the tables below.

Modes in one minute

Neovim has modes. Normal mode (the default) treats keys as commands. Press i to enter Insert mode and type text. Press Esc to go back. Use :w to save and :q to quit.

Learn the basics interactively. Run nvim, then type :Tutor for a 30-minute built-in lesson. It is the fastest way to become comfortable with modes and movement.

Code intelligence (TypeScript)

Language servers provide the IDE features. Open any .ts file and they start automatically. This setup enables the LazyVim extras for TypeScript, JSON, eslint and prettier.

KeysAction

Space c rRename a symbol everywhere
Space c aCode actions (quick fixes, organize imports)
Space c dShow the error on the current line

Completion appears as you type. Accept a suggestion with Enter or move through the list with Ctrl+n and Ctrl+p.

Git with lazygit

Open it with Space g g inside Neovim, with Ctrl+b then g in tmux, or by typing lazygit. The screen has panels for status, files, branches, commits and stash. Move with the arrow keys or h j k l, and press ? anywhere to see the keys for that panel.

KeysAction
SpaceStage or unstage the selected file
aStage or unstage all files
cCommit staged changes
P / pPush / pull
EnterOpen the selected file's changes line by line
qQuit lazygit

Inside Neovim, LazyVim also shows added, changed and removed lines in the left margin (gitsigns).

Mason

Mason is a package manager inside Neovim for the helper programs an editor needs: language servers, linters and formatters. It installs them into ~/.local/share/nvim/mason, so no sudo or global npm install is needed. LazyVim installs what your enabled extras require the first time you open a matching file.

Open the manager with Space c m or :Mason. Inside it, i installs the tool under the cursor, X uninstalls it and U updates it.

ToolJob
vtslsTypeScript language server
eslint-lspShows eslint problems as you type
prettierCode formatter
json-lspJSON validation and completion
tree-sitter-cliBuilds the syntax-highlighting parsers
lua-language-server, stylua, shfmtSupport for the Lua config and shell scripts

Plugins themselves are managed by lazy.nvim. Open it with Space l. Press U there to update all plugins, and commit the resulting lazy-lock.json if you keep the config in git.

Updating Neovim itself

Download the newer nvim-linux-arm64.tar.gz from the Neovim releases page, extract it into ~/.local/opt/, and point the ~/.local/bin/nvim link at the new folder. The other binaries update the same way.

Troubleshooting

Colors look wrong, or icons show as boxes

The terminal needs true-color support and a Nerd Font (a font that includes icon glyphs). Install one on the machine you connect from, such as JetBrainsMono Nerd Font, and select it in your terminal's settings.

Pressing Esc in Neovim feels slow

The tmux config already sets escape-time to 10 ms. If it is still slow, check that tmux was restarted after the config was written (tmux kill-server, then hb).

No completion or errors in a TypeScript file

Run :LspInfo to see whether vtsls is attached. Run :Mason to confirm it is installed. Open the file from inside the project folder so the server finds tsconfig.json.

Syntax highlighting is missing

Run :checkhealth nvim-treesitter. If tree-sitter-cli is missing, open Neovim normally and wait; the install runs in the background and can take a few minutes on a Pi.

Something in the config is broken

Run :checkhealth for a full report. As a last resort, move ~/.config/nvim aside and re-create it from the LazyVim starter template.

About the hb launcher. It is a small custom script. If one of its panes closes immediately, run the pieces by hand in a normal tmux session (nvim in one pane, npx vitest in another) and check the error message. Editing ~/.local/bin/hb is safe.
